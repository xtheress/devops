## Опишите основные примитивы Ansible

- Ответы
    Ansible — это система автоматизации управления конфигурациями, развёртывания приложений и оркестрации IT-инфраструктуры. Написан на Python с использованием декларативного языка YAML для описания сценариев (плейбуков), в которых описывается требуемое состояние системы.
    
    Control Node (Узел управления): Машина, на которой установлен Ansible и с которой выполняется управление. С неё запускаются команды и плейбуки по SSH к управляемым узлам.

    Managed Nodes (Управляемые узлы): Серверы или устройства, которыми управляет Ansible. На них не требуется установка агентов — управление идёт через SSH.

    Inventory (Инвентарь): Файл или скрипт с перечнем управляемых хостов (IP-адреса, имена, группы) для организации работы с множеством узлов.

    Playbook (Плейбук): Основной файл автоматизации в формате YAML, описывающий набор задач (tasks) или ролей и их последовательность для выполнения на целевых хостах.

    Роль: это модульный, хорошо структурированный комплект автоматизации, объединяющий связанные между собой задачи (tasks), обработчики (handlers), переменные (variables), шаблоны (templates) и файлы (files) 
    
    Tasks (Задачи): Отдельные операции, выполняемые Ansible, например установка пакетов, копирование файлов, запуск сервисов.

    Modules (Модули): Набор встроенных или сторонних библиотек для выполнения конкретных действий внутри задач, например, управление файлами, пользователями, процессами.

    Handlers (Обработчики): Специальные задачи, запускающиеся при изменениях состояния, например, перезапуск сервиса после обновления конфигурации.

    Variables (Переменные): Значения, используемые для настройки и параметризации плейбуков, позволяют делать конфигурации гибкими и повторно используемыми.

    Templates (Шаблоны): Файлы с динамической генерацией содержимого (обычно на Jinja2), например, для конфигурационных файлов, наполняемых переменными

## В чем разница pull и push модели?

- Ответы
    
    **Pull**-модель преполагает, что управляемые хосты подтягивают инструкции с мастер-сервера.
    
    **Push**-модель реализует подход, когда инструкции по желанию или по событию доставляются с управляющего на управляемые хосты.
    
    Ansible чаще всего используется для push-модели управления, но умеет и pull-модель.

## В чем разница между модулем и плагином**

- Ответ
    
    Модули что-то делают на хостах. Модули вызываются в задачах (tasks) плейбука
    
    Плагины расширяют функционал ансибла

## Для чего нужен ad hoc в ansible?

- Ответ
    
    Это режим работы ансибл когда запрос к серверу выполняется напрямую из командной строки, без создания дополнительных файлов.
